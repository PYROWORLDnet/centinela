## Cómo se designa a un nuevo maintainer

1. Un maintainer actual propone a la persona por escrito (issue o correo a `info@nodoia.app`).
2. La persona debe haber contribuido de forma sostenida: PRs fusionados, revisión cuidadosa de fuentes y respeto al [Código de Conducta](./CODE_OF_CONDUCT.md).
3. Todos los maintainers actuales deben estar de acuerdo.
4. Se actualiza esta lista en un PR y se le otorga permiso de revisión/aprobación en GitHub.
5. No se comparte acceso a la base de datos de producción, claves de API ni secretos de deploy salvo que el maintainer principal lo decida por separado.

## Qué no implica ser maintainer

- No da acceso a la base de datos de producción.
- No da derecho a saltarse el flujo de Pull Request.
- No autoriza a publicar credenciales, dumps ni datos no anonimizados.
